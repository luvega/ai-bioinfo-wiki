# 项目目录结构与可复现性

## 推荐目录（36 课时讲稿第 2 周给出）

```
project_root/
├── data_raw/         # 原始数据，永远不要覆盖、不要修改
├── data_processed/   # 清洗后数据
├── scripts/          # 全部分析代码（Python / R / Bash）
├── results/          # 图、表、模型输出
├── docs/             # 报告、说明、README
└── ai_logs/          # 每次 AI 协作的记录（6 字段模板）
```

## 原则

1. **原始数据只读**：永远从 `data_raw/` 读取，不就地修改。
2. **中间结果可追溯**：`data_processed/` 中的每个文件都要能追溯到某个 `scripts/*.py` + 日期。
3. **路径相对、不带绝对路径**：避免 `C:\Users\xxx\...`，否则别人/未来的你跑不通。
4. **文件命名规则**：日期 + 任务 + 版本 + 含义。**禁止** "最终版2"、"新新结果" 这类。
5. **依赖锁文件**：Python 用 `requirements.txt` 或 `pyproject.toml`，R 用 `renv::snapshot()`。
6. **README**：写清楚怎么跑、怎么解读结果、数据来源、AI 是怎么参与的。

## 与 AIDD 的对接

- AIDD [Ch.6 Bioinformatics Pipeline](../sources/AIDD_Bioinformatics_Course.md) 强调流程化思维：
  输入、处理工具、参数、输出文件、日志。这与本概念**一致**，
  本课程把生信 pipeline 的"参数+输入+输出"逻辑迁移到了医药数据。
- AIDD [Ch.12 GitHub Guide](../sources/AIDD_Bioinformatics_Course.md) 提供版本控制基础，
  可在第 2、17、18 周引用，让学生学会用 git 跟踪自己的项目。

## 与 AI 协作的关系

- AI 不会替你建目录，但**给 AI 看上下文之前**，先让它知道你的目录结构能避免幻觉。
- 推荐的 prompt 开头：

```text
我的项目目录结构是：
project_root/
├── data_raw/
│   └── 2026-05-21_clinical_marker.csv
├── scripts/
│   └── 01_clean_marker.py
└── results/

请帮我写 01_clean_marker.py 的初稿，要求 …
```

## 课程位置

- **第 2 周**：必修，建立"可复现"意识。
- **每次上机任务**：要求学生提交时附目录截图。
- **第 17-18 周项目**：评分项之一是"目录结构与文档规范度"。
