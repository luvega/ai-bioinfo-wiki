# 第 03 周：AI 辅助编程与 Python 快速入门 · 授课讲义

## 讲义使用说明

本讲是全课程的编程入口，面向没有系统编程背景的药学本科生。教师不需要在 2 学时内讲完 Python 语法体系，也不应把课堂变成软件安装课。本讲真正要完成的是一件事：让学生形成“先写规则、再读代码、最后核验 AI 输出”的工作方式。后续的数据清洗、统计分析、转录组矩阵处理、差异表达筛选和图表生成，都依赖这种工作方式。

本讲与前两周的连接是“从数据意识进入可复现操作”。前两周已经讨论医药数据的特点、分析流程和人机协作规范，本周开始把这些规范落到最小代码任务上。与后续周次的连接是“Python 作为可复核的工具语言”。学生不需要成为程序员，但必须能看懂一小段代码是否按照规则处理了缺失值、阈值和边界情况。

## 教学目标

本讲结束时，学生应能识别 Python 中的变量、列表、字典、条件和循环，能读懂 10 行以内的代码，并能用一个小数据集手算核验代码结果。更重要的是，学生要知道 AI 可以解释代码、定位报错、生成测试样本，但不能替代自己判断输入、输出、边界情况和医学含义。

## 课前导入

教师可以这样开场：

“从这一周开始，我们进入 Python。但请大家先不要把 Python 想成一门抽象的计算机课程。对药学专业学生来说，Python 首先是一个把规则写清楚的工具。药学研究里很多问题并不神秘，比如某个指标有没有缺失，某个值是否超过阈值，某个样本属于对照组还是处理组，某个基因列表里哪些结果值得进一步核验。只要这些规则需要重复执行，代码就有价值。”

接着可以提醒学生：“今天我们会使用 AI，但不是让 AI 代替我们写作业。我们要学习的是如何让 AI 成为解释器、调试助手和测试样本生成器。AI 给出的代码或解释，只能作为候选答案。真正决定它是否可信的，是我们能不能用小数据把它核验出来。”

这个导入有两个目的。第一，降低学生对编程的恐惧，把 Python 放回医药数据处理场景。第二，提前建立 AI 边界，避免学生误以为会提问就等于会编程。

## 药学场景

本讲使用一个极小的临床指标例子：一组血糖观测值中既有正常数值，也有缺失值，还有一个明显偏高的值。这个例子故意很小，因为小数据最适合手算核验。教师可以告诉学生，大型数据分析不是从复杂代码开始的，而是从一个可以手算的小例子开始确认规则是否正确。

课堂数据如下：

```python
glucose = [5.2, 6.1, 4.9, None, 12.8, 5.7]
```

教师先不要马上写代码，而是让学生观察这个列表。可以提问：“哪些值可以直接参与均值计算？哪个值表示缺失？哪个值可能需要标记为高风险？这里的高风险值应该删除，还是应该保留并标记？”预期回答是：`None` 表示缺失，不能直接参与求和；`12.8` 是偏高值，不应直接删除，因为它可能正是我们需要关注的信号；本例采用 `> 7.0` 作为课堂演示阈值。

这里要强调一个常见误区：异常值不等于错误值。缺失值和高风险值在处理策略上不同。缺失值需要过滤或插补，高风险值通常要保留并标记。这个区别会贯穿后续缺失值处理、异常值识别和组学结果筛选。

## 核心数据结构

本讲只讲五个最小语法单元：变量、列表、字典、条件和循环。教师讲解时不要逐条扩展成完整语法课，而要始终回到数据场景。

变量可以理解为给一个值起名字。例如 `threshold = 7.0`，意思是把高风险阈值保存下来，后面代码统一引用这个名字。列表可以理解为一组观测值，例如血糖列表、IC50 列表、样本编号列表或基因名列表。字典可以理解为映射关系，例如样本 ID 到分组，患者编号到年龄，基因 ID 到 gene symbol。条件用于表达判断，例如“不是缺失值”“大于阈值”“属于处理组”。循环用于批量处理一组样本，使同一条规则能重复应用。

教师可以把五个语法单元串成一句话：“我们把阈值存在变量里，把一组指标放进列表里，用条件判断哪些值可用，再用循环或列表推导式批量处理，最后得到可以核验的结果。”

## 代码阅读三问

在展示代码前，教师应先训练学生问三个问题。第一，输入是什么？本例输入是 `glucose` 列表，其中包含五个有效数值和一个缺失值。第二，规则是什么？本例规则是过滤 `None`，计算有效数值均值，并找出大于 `7.0` 的高风险值。第三，输出是什么？输出应包括有效数值列表、均值和高风险值列表。

这三个问题比语法细节更重要。学生如果不知道输入、规则和输出，即使代码能运行，也不知道结果是否合理。反过来，如果学生能先写出规则，即使语法暂时不熟，也可以借助 AI 或教材把规则翻译成代码。

## 最小 Python 实现

课堂核心代码可以控制在三行：

```python
valid = [x for x in glucose if x is not None]
mean_glucose = sum(valid) / len(valid)
high_risk = [x for x in valid if x > 7.0]
```

教师讲第一行时，要说明这不是为了炫耀列表推导式，而是在表达一个简单规则：“从 `glucose` 中拿出每个 `x`，只保留不是 `None` 的值。”如果学生觉得这一行难，可以先用自然语言解释，再改写成更直观的循环。这里的重点不是让学生背语法，而是让学生看出 `if x is not None` 对应“排除缺失值”。

讲第二行时，要提醒学生 `sum(valid)` 和 `len(valid)` 的分母都必须基于过滤后的有效数值。如果直接使用原始列表，不仅 `None` 会导致报错，而且即使没有报错，把缺失值算进分母也会改变均值。这个点可以为后续缺失值处理课程埋下伏笔。

讲第三行时，要说明高风险筛选并没有删除 `12.8`，而是把它作为结果标记出来。对于医药数据，偏高、偏低或异常的值往往是研究关注对象。课堂上要避免形成“异常就删掉”的错误习惯。

## 人工核验

教师带学生手算一次结果。有效数值是 `[5.2, 6.1, 4.9, 12.8, 5.7]`，有效样本数是 `5`，总和是 `34.7`，均值是 `34.7 / 5 = 6.94`。大于 `7.0` 的值只有 `12.8`，所以高风险列表是 `[12.8]`。

这里要慢下来讲。对初学者来说，手算不是低级步骤，而是建立信任的步骤。学生以后会面对更复杂的数据表、上千个基因、上万个检验结果，无法逐个手算。但他们仍然应该先用小样本验证代码逻辑，再把同一逻辑扩展到大数据。今天这个血糖例子就是一个缩小版的分析流程。

教师可以板书一个小表：

| 项目 | 预期结果 | 核验方式 |
|---|---:|---|
| 有效数值 | `[5.2, 6.1, 4.9, 12.8, 5.7]` | 检查是否排除 `None` |
| 有效样本数 | `5` | 手数列表长度 |
| 均值 | `6.94` | `34.7 / 5` |
| 高风险值 | `[12.8]` | 与阈值 `> 7.0` 比较 |

## 课堂互动脚本

教师提问：“如果我直接写 `sum(glucose)`，会发生什么？”预期学生可能回答“会求和”或“不确定”。教师此时可以演示或解释错误：Python 不能把数字和 `None` 相加，所以会出现类型错误。追问：“这个错误是坏事吗？”正确引导是：错误信息不是坏事，它告诉我们规则没有处理缺失值。

教师继续提问：“如果我把 `None` 改成 `0`，代码是不是就能算？”学生可能会说能算。教师要追问：“能算是否等于合理？”这里要强调，缺失值不是 0。把缺失值当作 0 会人为降低均值，除非有明确医学或数据采集理由，否则不能这样处理。

第三个问题是：“`12.8` 是否应该删除？”学生可能会说它太高，应该删除。教师要纠偏：这个值可能是错误，也可能是真实高风险信号。是否删除需要回到数据来源、测量记录和研究目的。今天的课堂规则是标记它，而不是删除它。

## AI 协作边界

本讲推荐的 AI 提示词是：

```text
请逐行解释下面这段 Python 代码的作用，并指出它是否正确处理了 None 缺失值。请先解释，不要直接重写完整代码。
```

教师要解释为什么这样写提示词。第一，“逐行解释”迫使 AI 对代码结构负责，而不是直接给一个新答案。第二，“是否正确处理 None 缺失值”把审计重点明确告诉 AI。第三，“不要直接重写完整代码”避免学生跳过理解过程。

教师可以展示一段 AI 输出，让学生检查三个点：AI 是否提到 `None`，是否解释了 `valid`、`mean_glucose` 和 `high_risk` 三个输出，是否把医学含义说得过头。若 AI 说“12.8 表示患者患有某疾病”，教师必须指出这是不合格输出。单个血糖值只能提示风险，不能直接推出诊断结论。

## AI 调试与测试

教师可以给出一个错误版本：

```python
mean_glucose = sum(glucose) / len(glucose)
```

然后让学生把错误交给 AI，要求 AI 解释为什么报错。合格解释应指出 `glucose` 中包含 `None`，`sum()` 无法把 `None` 与浮点数相加。更好的解释还会提醒先过滤缺失值。

接着让 AI 生成边界测试样本，但教师要强调测试样本也要人工审查。可以给出三组：

| 测试样本 | 预期输出 |
|---|---|
| `[5.0, 6.0]` | 均值 `5.5`，无高风险 |
| `[None, 8.0]` | 均值 `8.0`，高风险 `[8.0]` |
| `[None]` | 无有效值，不能直接计算均值 |

第三组最重要，因为它暴露了新边界：如果所有值都是缺失值，代码中 `len(valid)` 为 0，继续除法会出错。教师可以说明，真实数据处理并不是写出三行代码就结束，而是要逐步补充边界情况。

## 生信扩展

本周不要求安装 Biopython，但可以用一个序列例子说明 Python 在生命科学中的用途：

```python
seq = "ATGCGTAC"
length = len(seq)
gc = (seq.count("G") + seq.count("C")) / length
```

教师解释时只需指出：这里的输入从血糖列表变成了 DNA 序列，但思路没有变。仍然是先明确输入，再写规则，最后核验输出。`len(seq)` 对应序列长度，`seq.count("G") + seq.count("C")` 对应 GC 碱基数量。这个例子是为了说明 Python 可以处理生命科学数据结构，不是为了展开完整生信分析。

## 板书与页面节奏

建议第 1-3 页快速通过，用于建立课程定位。第 4 页讲五个语法单元时，每个单元只给一个药学例子，不展开语法细节。第 5-8 页是本讲核心，应占用最多时间，尤其是缺失值过滤、均值手算和高风险标记。第 9-10 页进入 AI 协作，重点是审计 AI，而不是展示 AI 多么强。第 11 页作为拓展，不应超过 8 分钟。第 12 页收束时让学生完成出口卡。

如果时间不足，宁可删掉生信扩展，也不要压缩人工核验和 AI 审计。因为本讲真正的能力目标不是“见过 Biopython”，而是“知道代码结果必须被核验”。

## 课堂任务

课堂任务分三步完成。第一步，学生先不用代码，手动写出血糖列表的有效数值、均值和高风险值。第二步，学生对照教师给出的三行 Python 代码，逐行说明每一行对应哪一条自然语言规则。第三步，学生把错误代码或自己的代码交给 AI 解释，但必须记录 AI 是否正确指出 `None` 的处理问题。

课堂任务的提交物可以很短，但必须包含四项：自然语言规则、Python 代码、手算核验结果、AI 审计记录。教师检查时不只看代码是否能运行，还要看学生是否能解释为什么这样处理缺失值和高风险值。

## 常见误区与纠偏

第一个误区是把会运行代码等同于会编程。纠偏方式是反复追问输入、规则和输出。如果学生无法解释代码的输入和输出，就不能算真正理解。

第二个误区是把 AI 输出当标准答案。纠偏方式是要求学生保留 AI 协作记录，写清楚原始问题、AI 输出、自己的核验方法和最终采用的代码。

第三个误区是把缺失值当作 0。纠偏方式是用均值变化说明这种处理会改变结果，并说明缺失值处理需要依据数据采集背景。

第四个误区是看到异常值就删除。纠偏方式是区分错误值、极端值和高风险信号。药学数据中，异常现象往往正是需要进一步核验的对象。

## 课堂收束

教师可以这样结束本讲：

“今天我们没有系统学习 Python 的所有语法，但我们建立了一个更重要的习惯：先把问题写成规则，再把规则翻译成代码，最后用小数据核验结果。AI 可以帮助我们解释代码、定位错误、生成测试样本，但它不能替我们判断医学含义，也不能替我们确认边界情况。以后我们面对更大的数据表、更复杂的统计模型和更漂亮的图表时，仍然要回到这三个问题：输入是什么，输出是什么，我怎样知道结果是对的。”

这段收束要明确过渡到后续课程：下一步学生会继续接触 R、数据框、数据读取和清洗。今天的三步法会反复出现。

## 课后练习与评分点

课后练习要求学生把课堂血糖例子改写成一个药效指标列表。列表中必须包含至少 6 个值，其中至少 1 个缺失值、1 个高于阈值的值和 1 个边界值。学生需要提交自然语言规则、Python 代码、3 个测试样本、预期输出和一条 AI 协作记录。

评分点包括：第一，是否正确处理缺失值，而不是把缺失值当作 0；第二，是否明确阈值规则，并区分标记和删除；第三，是否给出可手算或可解释的预期输出；第四，AI 协作记录是否包含人工核验，而不是只粘贴 AI 答案；第五，代码是否能在本机 Python 环境运行。

## 待核验

课堂代码进入正式 PPT 前需要重新运行。若使用 Biopython 或其他专业库作为扩展案例，只展示数据结构直觉，不要求学生本周安装。若教师希望加入真实临床指标，应确认指标单位、阈值来源和教学用途，避免把课堂演示阈值误讲成临床诊断标准。
