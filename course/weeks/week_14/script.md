# 第 14 周：转录组数据分析基础 · 授课脚本

## 开场

同学们，前面我们已经学习了数据清洗、统计分析和图表表达。从本周开始，我们把这些能力放到组学数据场景中。今天先讲转录组数据分析基础。一个核心问题是：我们在很多文章里看到的表达矩阵，到底是怎么来的？

RNA-seq 的目标是测量基因表达水平。但测序仪最初给我们的不是一张整齐的表格，而是一批 reads。也就是说，后续 DESeq2、火山图、热图和功能富集分析的起点，并不是凭空出现的表达矩阵，而是一系列质控、比对和计数步骤之后得到的 count matrix。

## 讲授主线

先建立完整链条。第一步是从公共数据库或测序平台得到 FASTQ 文件。FASTQ 记录 reads 序列和质量信息，所以它还不是统计分析用的表。第二步是质量控制，检查 reads 的质量分布、接头污染、低质量碱基等问题。第三步是 trimming，去掉低质量部分。第四步是把 reads 比对到参考基因组或转录组，得到 SAM 或 BAM 文件。第五步是对 BAM 排序和索引，方便后续程序快速访问。第六步是 feature extraction，把 reads 分配到基因或转录本上，得到 gene-by-sample 的 count matrix。

这里要强调，count matrix 是后续统计分析的真正入口。它通常以基因为行、样本为列，数值表示 reads 计数。与此同时，还必须有 metadata，记录样本分组、处理条件、批次、性别、时间点等信息。如果 count matrix 的列名和 metadata 的样本名不一致，后面所有分析都会出问题。

接下来讲标准化的直觉。不同样本的总 reads 数可能不同，测序深度也可能不同。因此，不能直接拿两个样本的原始 counts 做比较。标准化的目的，是让不同样本在可比尺度上进行统计分析。今天不展开复杂模型，只要求大家知道：原始 counts 需要经过方法处理后，才适合用于组间比较。

## 课堂预期答案

- `count matrix` 行代表基因，列代表样本，数值代表 reads 计数。
- `metadata` 记录样本分组、批次等信息，必须与 count matrix 的列名对齐。
- 每个样本总 counts：`Ctrl_1 = 650`，`Ctrl_2 = 660`，`Drug_1 = 678`，`Drug_2 = 685`。
- 不能直接比较原始 counts，因为不同样本的总 reads 数、测序深度或文库规模不同。
- 合格 AI 输出必须按“输入文件、处理步骤、输出文件、可能质量问题”组织，并标出需要人工核验的环节。

## 课堂互动

展示一个 3 个基因、4 个样本的小矩阵，让学生指出行、列和值分别代表什么。然后给出一个 metadata 表，让学生检查样本名是否一一对应。接着让学生计算每列总 counts，并讨论：如果 Drug_1 总 reads 明显高于 Ctrl_1，能不能直接说所有基因在 Drug_1 中表达更高？

这个问题是本讲的关键。学生如果能回答“不能，需要考虑测序深度和标准化”，就已经建立了进入差异表达分析的前提。

## 上机/讨论引导

学生不需要在本周完整跑命令行上游流程。练习重点是读取小型 count matrix、检查 metadata、计算样本总 counts，并写出对标准化必要性的解释。可以让 AI 帮忙把 FASTQ 到 count matrix 的流程整理成表格，但要求学生标出每一步的输入、输出和可能质量问题。

## 收束

本讲的核心是理解数据链条。表达矩阵不是天然存在的，它来自测序 reads 的一系列处理步骤。只有知道 count matrix 从哪里来，我们才有资格判断后面的差异表达、可视化和功能解读是否可信。
## 样板周授课补充

### 教学目标
让学生理解 RNA-seq 表达矩阵不是天然存在的表格，而是由测序 reads 经过质控、比对和计数得到。

### 药学场景
围绕药物处理前后表达变化的问题，说明为什么进入差异表达前必须知道 count matrix 的来源。

### 核心数据结构
FASTQ 是原始 reads，SAM/BAM 是比对结果，count matrix 是基因层面的计数，metadata 记录样本分组。

### 课堂任务
学生用小矩阵检查样本名、计算总 counts，并口头解释测序深度差异带来的比较偏差。

### AI协作边界
AI 可辅助整理流程图和术语表，但每一步输入、输出和质量风险必须由学生标注确认。

### 课后练习
把 FASTQ 到 count matrix 的流程写成四列表：输入、处理、输出、质量问题。
